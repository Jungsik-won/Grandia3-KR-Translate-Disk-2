# 그란디아 III 렌더링 이벤트 자막 작업 절차

## 플레이 중 새 이벤트를 발견했을 때

1. 이벤트에 들어가기 직전에 게임 내 메모리카드에 저장한다.
2. 화면 녹화를 켠 뒤 이벤트 시작 3~5초 전부터 끝난 뒤 3~5초까지 녹화한다.
3. 이벤트 음성이 나오는 동안 런타임 추출기로 아래 두 주소를 읽는다.
   - 이벤트/음성 정보: `0x001FEA20`
   - 현재 리소스 경로: `0x0020DC00`
4. 이벤트가 여러 장면으로 이어지면 녹화를 끊지 않는다. 값이 바뀌는 장면마다 추출 결과를 한 번씩 저장한다.
5. MOVIE 파일로 재생되는 영상인지, 3D 캐릭터가 움직이는 렌더링 이벤트인지 함께 적는다.

## Codex에 보내는 고정 양식

아래 양식을 복사해서 값과 파일만 채운다.

```text
새 렌더링 이벤트 자막 작업해줘.

디스크: 1 또는 2
장소/장면: 예) 유우키 집에서 미란다가 유우키를 찾는 장면
MDZ: DATA/00000000.MDZ
이벤트 음성 ID: 0x0000
GR3_STR 스트림: 0x00
0x001FEA20: 추출기에 표시된 16바이트
녹화 파일: /절대/경로/녹화.mp4
이벤트 직전 메모리카드 저장: 있음
재생 종류: 렌더링 이벤트 또는 MOVIE
```

한 이벤트에서 값이 바뀌었다면 같은 메시지 아래에 두 번째·세 번째 관측값을 이어서 붙인다.

## Codex가 처리할 작업

1. MDZ와 음성 스트림의 소유 관계를 확인한다.
2. 녹음에서 일본어를 전사하고 문맥에 맞춰 한국어로 번역한다.
3. 음성과 스트림 파형을 맞춰 자막 시작·종료 시각을 계산한다.
4. 현재 MDZ 경로, request slot, SPU2 active voice를 대조해 실제 스트림을 확정한다.
5. 공용 매니페스트와 cue JSON을 갱신하고 `GR3SUB.BIN` 후보를 다시 만든다.
6. 자동 테스트와 SLPM/`GR3SUB.BIN` 정적 검증을 거친 뒤 테스트 ISO를 만든다.

## 확정 저장 구조

```text
SLPM_659.76 / SLPM_659.77
└─ 공용 파일 로더·렌더러·고정 크기 탐색 루프만 저장

ISO 루트 GR3SUB.BIN
└─ 4bpp 글꼴 + 문장 + 싱크 + MDZ 경로표 + sample/event 조회표 누적

DATA/*.MDZ
└─ 자막 payload를 넣지 않으며 기존 중앙 번역 리소스를 그대로 보존
```

새 이벤트를 추가할 때 SLPM이나 MDZ에 이벤트별 payload를 계속 붙이지 않는다.
매니페스트와 cue JSON을 누적해 `GR3SUB.BIN`만 다시 만들며, 경로표와 sample/event
조회표도 외부 파일에 있으므로 이벤트 수가 늘어도 SLPM 코드·데이터 사용량은
일정하다. 같은 음원과 cue를 쓰는 MDZ 별칭은 동일 조회표와 cue 범위를 공유한다.

새 이벤트는 실제 PCSX2에서 장면 진입, 자막 전체, 이벤트 종료, 필드 복귀까지
확인해야 `RUNTIME_PASS`로 승격한다. 이전 상태저장은 구형 `GR3SUB.BIN`이 적재된
RAM을 복원할 수 있으므로 새 ISO 완전 부팅 뒤 만든 상태저장만 사용한다.

ISO 생성 전 후보 준비 명령:

```bash
python3 tools/build_external_subtitle_container_test.py \
  --source-iso "/중앙 누적 Disc 1 ISO.iso" \
  --manifest data/scenario/gr3_rendered_event_subtitles.json \
  --output-dir build/gr3sub-bin-preflight \
  --prepare-only
```

이 명령은 `SLPM_659.76`, `GR3SUB.BIN`, 검증 보고서까지만 만들며 ISO 파일은
생성하거나 수정하지 않는다. 실제 ISO 빌드에서는 반드시 중앙 세션이 완성한 최신
누적 ISO를 `--source-iso`로 사용한다.

## 패치 확인 방법

1. PCSX2를 완전히 종료한다.
2. 새 테스트 ISO를 실행한다.
3. 이전 상태저장이 아니라 게임 내 메모리카드 저장을 불러온다.
4. 이벤트 직전까지 이동해 이벤트 전체를 확인한다.
5. 반복 확인이 필요하면 새 ISO로 부팅한 뒤 이벤트 직전에서 새로운 상태저장을 만든다.

이전 ISO에서 만든 상태저장은 실행파일과 메모리 내용을 함께 복원하므로 새 자막 패치 검증에 사용하지 않는다.

