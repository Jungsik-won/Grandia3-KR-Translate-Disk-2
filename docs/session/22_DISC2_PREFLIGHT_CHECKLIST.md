# Grandia III Disc 2 한국어화 — 누락 방지·통합 빌드 체크리스트

이 문서는 Disc 1 플레이테스트에서 확인된 미번역·글자 깨짐·이벤트 정지 문제를
Disc 2에서 반복하지 않기 위한 필수 절차다. Disc 2 ISO 생성은 아래 항목을 모두
통과한 뒤에만 허용한다.

## 1. 기준본과 빌드 원칙

- 입력은 항상 CLEAN `Grandia III (Japan) (Disc 2).iso`다.
- 이전 테스트 ISO나 일부 수정 MDZ를 다음 빌드의 기준으로 사용하지 않는다.
- 각 세션의 정식 CSV/JSON/DB를 한 번에 모아 CLEAN 추출본에 누적 적용한다.
- 동일 파일을 담당하는 여러 도메인은 세션별 바이너리 덮어쓰기가 아니라 한 번의
  누적 빌드로 합친다.
- 모든 후보는 원본 ISO entry, 원본 해시, 후보 해시, 크기, 패치 수를 manifest에
  남긴다.

## 2. 번역 모집단 잠금

Disc 2 전체 파일을 먼저 전수 추출하고 아래 도메인별 레코드 수를 고정한다.
플레이 중 발견된 한두 문구만 추가하는 방식으로 완료 판정을 내리지 않는다.

- 시스템·상태·장비·공통 UI
- 아이템 이름·설명·효과·입수 팝업
- 아군 이름·기술명·기술 설명
- 적 이름과 적 행동/기술명 전체
- 전투 작전명·작전 도움말·튜토리얼/연출 도움말 전체
- 전투 중 화면에 표시되는 캐릭터 전술 대사 전체(`battle_voice` 음성 목록과 구분)
- 필드명·마을명·로딩/세이브 지명
- 필드 행동 라벨과 주변 안내 메시지 전체
- 시나리오 대사, 선택지, timed dialogue
- 일반 NPC 대사와 NPC 이름판
- 세이브·회복·외출 등 이벤트 메뉴

각 도메인은 `추출 수 = 정식 CSV 수 = translation.db 수 = 빌드 패치 수`를
검증한다. `UNTRANSLATED`, 빈 한국어, 미해결 `<Gxxxx>`, 일본어 잔존이 있으면
ISO 생성 전 상태는 미완료다.

GR3 전투 전술 대사는 Disc 1처럼 상대 포인터표와 인라인 제어가 별도일 수 있다.
포인터 수, 빈 항목 수, 비어 있지 않은 호출 수, 고유 문장 수를 먼저 잠그고
`<NAME:dddd>` 토큰의 순서와 수, 줄바꿈 제어 수를 번역 전후 대조한다. 한글 풀이
원래 할당량을 넘으면 다음 리소스를 덮지 말고 소속 MDT 청크 안에서 relocation한
뒤 모든 포인터를 갱신한다.

필드명·상점명·행동 라벨은 CP932/compact 연속 문자열 검색만으로 모집단을
결정하지 않는다. Disc 1에서 확인된 `u32 count + u8 glyph_counts + u32 offsets +
u16 logical glyph indices` 구조를 Disc 2 DATA MDT 전체에서 전수 탐색하고,
`테이블 수·발생 수·고유 문자열 수`를 잠근다. 새 변형 구조가 나오면 별도 모집단으로
추가한다.

오프셋표 시작점은 반드시 `align4(0x10 + count)`로 판정한다. Disc 1 v14처럼
`align8`만 허용하면 4바이트 정렬형 컨테이너가 대량 누락되므로, Disc 2에서도
4바이트 정렬형 합성 테스트와 발견 모집단 해시를 빌드 게이트로 고정한다.

## 3. 폰트맵 고정 절차

- Disc 1에서 검증된 글리프 배치 순서와 물리 슬롯을 보존한다.
- Disc 2 신규 한글만 현재 사용량 감사에서 안전한 빈 슬롯에 추가한다.
- 새 글자 추가를 이유로 기존 1바이트 한글을 다른 슬롯으로 전면 재배치하지 않는다.
- 최종 폰트맵 하나로 폰트 bitmap과 FIELD/BATTLE/GR3/DATA 텍스트를 모두 다시
  인코딩한다. 구형 폰트 바이너리와 신형 인코딩 바이트를 혼합하지 않는다.
- 고정 크기 문자열은 실제 encoded byte 길이로 검사한다. 문자 수만으로 적합성을
  판단하지 않는다.

## 4. 시나리오 내부 참조 재배치

번역문 길이가 달라지는 DATA 시나리오는 member 시작·크기뿐 아니라 이벤트 내부
참조를 함께 재배치한다. 현재 입증된 형식은 다음과 같다.

```text
10 30 <u16 target>              member-data base 상대
10 30 <byte> <u16 target> ...   record 상대 NPC/face 변형
10 00 <u16 target>              member-data base보다 4바이트 앞을 기준
10 30 ... 10 00 <u16 target>    paired branch/merge; member-data base 상대
```

`10 00` 형식은 세이브 복귀와 연속 캠프 NPC 이벤트 진입에 사용된다. 이 값을
갱신하지 않으면 저장 후 조작 불가, 첫 NPC 대화 후 다음 NPC 호출 불가가 발생한다.
paired 형식은 앞의 `10 30`과 4·6·8바이트 간격으로 결합되며 선택지, 금액 검사,
NPC·맵 설정 합류점에 쓰인다. suffix 기반 base-4 형식과 같은 좌표계로 처리하지
않는다.

Disc 2에서는 위 형식만 믿고 종료하지 않는다. 원본과 후보를 비교해 이동한
16비트 참조 후보를 전수 감사하고, 반복되는 새 명령형이 보이면 명령 구조와
좌표계를 입증한 뒤 재삽입기와 회귀 테스트에 추가한다. 번역문 안에서 우연히
같은 바이트가 나온 경우는 명령으로 취급하지 않는다.

## 5. 정적 검증 필수 조건

- 모든 변경 MDZ의 `MDZ → MDT → MDZ → MDT` 왕복 일치
- packer가 공통 출력 파일명을 쓰더라도 각 DATA 후보를 원래 ISO entry stem으로
  보존하고, 출력 파일 수와 고유 경로 수가 대상 컨테이너 수와 같은지 확인
- 모든 scenario descriptor 시작점·선언 크기·record/chunk 크기 일관성
- 비어 있지 않은 member alias 0
- 메시지의 member 경계 침범 0
- 내부 참조 target의 번역문 바이트 내부 착지 0
- 모든 u16 참조 범위 초과 0
- 고정 크기 풀 overflow 0
- 상대 포인터 문자열 풀의 번역문 내부 오착지 0, 전 포인터 역디코딩 불일치 0
- 최종 ISO 역읽기 해시가 각 후보 해시와 전부 일치
- 수정 대상 외 ISO entry가 CLEAN 원본과 byte-identical

## 6. 런타임 통과 동선

다음 화면은 Disc 2 초반부터 대표 지점을 정해 직접 확인한다.

- 로딩·세이브 화면의 지역명
- 마을 안/밖 출입 버튼과 지역명
- 일반 NPC 이름판과 연속 NPC 대화
- 선택지 선택 후 다음 이벤트 진행
- 세이브 포인트 저장 후 필드 조작 복귀
- 아이템 입수 팝업
- 필드 상자·조사 안내 연속 메시지
- 전투 작전 할당창의 작전명·설명
- 아군과 적이 쓰는 기술명
- 전투 튜토리얼·연출 도움말
- 긴 대사의 줄바꿈, 끝 문장부호, 글자 출력 속도

각 항목은 스크린샷/영상, ISO 경로, scene/record ID, 사용한 후보 해시를 기록한다.
정적 PASS는 런타임 PASS를 대신하지 않는다.

## 7. 중앙 세션 승인 조건

중앙 세션은 다음 자료가 모두 있을 때만 Disc 2 ISO 생성을 승인한다.

- 도메인별 정식 산출물과 고정된 모집단 수
- 동기화된 `translation.db`
- 최종 폰트맵과 글리프 감사 보고서
- 전체 누적 replacement plan
- 시나리오 내부 참조 감사 보고서
- PRE-ISO 검증 PASS
- DB 카테고리별 행 수와 물리 후보 소비 수가 같은 runtime coverage 감사 PASS
- CLEAN 원본 기반 빌드 명령과 출력 경로
- 런타임 필수 동선 체크 결과

Disc 1과 Disc 2에 byte-identical 리소스가 있어도 Disc 1의 게임 검증 상태를 Disc 2에
자동 승격하지 않는다. 동일 바이트는 구조 증거로 활용하되 Disc 2 동선에서 다시
확인한다.

## 8. 다중 NPC 선택 이벤트 보존 게이트

Disc 1의 배 식사 장면처럼 한 화면에서 NPC 커서를 옮겨 여러 대화를 완료해야 하는
이벤트는 일반 선형 대화와 별도 모집단으로 다룬다. 알려진 참조형 검증이 PASS여도
NPC 선택 완료 콜백이나 대화 완료 비트가 해석되지 않으면 번역 레코드를 승인하지
않는다.

- 번역 전후 NPC 선택 수와 각 선택의 진입·복귀 목표를 대조한다.
- 모든 NPC 대화를 한 번씩 열고 같은 NPC 재선택, 마지막 NPC 선택, 장면 종료를
  런타임으로 확인한다.
- 새 콜백 참조형이 입증되지 않았으면 `--preserve-original-records`로 레코드 전체를
  원본 보존하고, 보존 행 수를 최종 번역 소비 수에서 명시적으로 차감한다.
- 최종 ISO에서 보존 레코드를 역추출해 CLEAN 원본과 바이트 일치를 확인한다.
- 저장 상태가 이벤트 실행 중 메모리를 포함할 수 있으므로 장면 진입 전 인게임
  세이브나 이전 상태에서도 재시험한다.

Disc 2 빌드는 위 다중 NPC 선택 이벤트 목록과 런타임 결과가 없으면 중앙 세션에서
승인하지 않는다.

## 9. GR3 렌더링 이벤트 음성 자막

Disc 1/2의 `GR3.IDX`, `GR3_STR.IDX`, `GR3_STR.STZ`와 `DATA/*.MDZ` 391개는
전수 SHA-256 비교에서 모두 byte-identical이다. 따라서 렌더링 이벤트의 공통 음원,
전사, 번역, 60Hz cue와 입증된 MDZ 자막 패키지는 두 디스크가 공유한다. 빌더는
실행 파일 entry만 `SLPM_659.76` 또는 `SLPM_659.77`로 자동 선택한다.

다만 Disc 1의 런타임 결과를 Disc 2에 자동 승격하지 않는다. 각 Disc 2 호출 장면에서
다음을 다시 확인한다.

- active sample이 작업 큐의 승인 trigger와 일치
- 현재 `DATA/*.MDZ` resource가 승인 매핑과 일치
- 이벤트 진입 전 필드, 첫 cue, 한 줄/두 줄, 마지막 cue와 소거 정상
- 스킵·분기·중간 진입 시 timer 재동기화 정상
- 이벤트 종료 후 다음 필드와 다음 이벤트 진행 정상

공통 작업 큐는
`audio/manifests/gr3_stream_inventory/gr3_rendered_event_workqueue.csv`, 상태저장 관측은
`tools/capture_gr3_event_observation.py`, 전체 절차는
`docs/scenario/gr3-rendered-event-subtitle-pipeline-20260827.md`를 기준으로 한다.
