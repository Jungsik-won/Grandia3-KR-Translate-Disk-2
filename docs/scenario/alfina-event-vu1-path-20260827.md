# 알피나 방 이벤트: VU1/GIF 경로 메모

> 최종 상태: 실제 알피나 방 렌더링 이벤트에서 프레임마다 유지되는 GS
> 사각형 출력에 성공했다. 아래의 이전 시험 기록은 실패 경로를 포함하며,
> 최종 성공 경로는 문서 끝의 `pre-SIGNAL 삽입 성공` 절에 정리한다.

대상 상태는 PCSX2 저장 상태 04(이벤트 전)와 05(첫 보이스 재생 중)이며,
현재 작업본 v19 ISO와 대응한다.

## 확인된 사실

- 두 상태 모두 VIF1 DMA 채널의 CHCR은 `0x10000045`로 활성 상태다.
- VIF1의 현재 MADR/TADR는 다음과 같이 상태에 따라 달라진다.

| 상태 | VIF1 MADR/TADR |
| --- | --- |
| 04 | `0x01F39D50` |
| 05 | `0x01F4B140` |

- 상태 05의 해당 동적 버퍼는 VIF `DIRECT` 명령과 GIF 패킷을 포함한다.
  따라서 이 연출은 일반 필드 대사 렌더러가 아니라 VIF1 → VU1/GIF 합성
  경로를 실제로 사용한다.
- VU1 micro memory는 04/05에서 완전히 동일하고, VU1 data memory는 크게
  달라진다. 같은 VU1 프로그램에 이벤트별 데이터/패킷만 공급되는 구조다.

## 중요한 패킷 판독

상태 05 버퍼의 `0x01F4B22C`에는 `DIRECT 6` 명령이 있고, 바로 뒤의 여섯
QW는 GIF A+D 패킷이다. 여기에는 `BITBLTBUF`(GS 레지스터 `0x50`),
`TRXPOS`(`0x51`), `TRXREG`(`0x52`), `TRXDIR`(`0x53`)가 포함된다.
즉 이 구간은 텍스처 전송의 시작이다.

이 자리를 자막용 스프라이트로 덮어쓰면 이어지는 이미지 전송과 GS 상태를
깨뜨릴 수 있으므로, 삽입 지점으로 사용하지 않는다.

## 결론과 다음 분석 기준

일반 필드 메시지 콜백(`FIELD_SCENARIO_MESSAGE_ANALYZE`)은 실제 사용자
화면 시험에서 이 연출에 합성되지 않았으므로 기각한다. 반면 이벤트 전용
VIF1/GIF 경로는 존재가 확인됐고, 자막은 DMA 체인의 안전한 끝에 별도의
GIF 스프라이트 패킷을 추가하는 방식으로 넣을 가능성이 있다.

다음 단계는 현재 MADR에서 시작하는 DMA 태그 체인을 복원해, 텍스처 전송
이후의 안전한 종료 태그와 길이/연결 필드를 찾는 것이다. 이 단계가 끝나기
전에는 추가 ISO 사용자 시험을 만들지 않는다.

## 상태 6 체인 및 상태 7 저장상태 시험

상태 6의 VIF1 MADR/TADR는 `0x01F57DC0`이고, 여기서는 유효한 CNT/REF
DMA 태그 체인을 2,246개 연속으로 복원할 수 있었다. 체인은 모델 데이터의
VIF UNPACK 및 GS 텍스처 전송 `DIRECT` 패킷으로 구성된다.

마지막 더미 REFE 태그를 `END + DIRECT(4)` 흰색 스프라이트로 바꾼 별도
저장상태(슬롯 7)를 만들었으나, 사용자 화면에서 스프라이트는 보이지 않았다.
이는 저장상태 복원 뒤 이 배치가 게임 코드로 재작성되거나 뒤이은 렌더 패스가
그 결과를 덮는다는 것을 뜻한다. 저장상태의 단발성 메모리 패치는 렌더 삽입
방법으로 기각한다. 다음 단계는 VIF1 체인을 **매 프레임 작성·제출하는 게임
코드**의 호출부를 찾는 것이다.

## PCSX2 실행 추적 시도

상태 6을 복원한 뒤 이벤트를 재생한 PCSX2 실행 로그에는 VU1 micro-program의
연속 진입(`0x0080`, `0x0908`, `0x0A28`, `0x21C0`, `0x23F0`, `0x2518`,
`0x32A8`, `0x36A8` 등)이 남았다. 저장상태에서 보인 VIF1/VU1 경로가 실제
재생 중에도 매 프레임 활성화된다는 독립적인 확인이다.

다만 사용 중인 PCSX2 배포본은 활성화한 `vifcode`/`dmac`/`gif` trace를
파일 로그에 세부 DMA 주소나 VIF 명령으로 출력하지 않고 microVU 캐시 기록만
남긴다. 따라서 이 방법만으로는 VIF1 체인을 제출하는 EE 함수 주소를 얻을 수
없으며, 이후 단계는 게임 실행 파일의 렌더 큐 작성 코드 분석으로 진행한다.

## 최종 SIGNAL 호출부 시험과 공용 플러시 시험

`0x00145800`은 3 QW짜리 GS SIGNAL 패킷을 만든 뒤 `0x00163520`을 호출한다.
처음에는 이 호출부 `0x00145848`을 최종 합성 지점으로 보고 생짜 GS
스프라이트를 덧붙였으나, ISO는 정상 실행되어도 화면에는 표시되지 않았다.

저장상태의 EE scratchpad를 다시 확인한 결과 `0x001633F0`/`0x001634D0`/
`0x00163520`은 메인 메모리의 대형 체인이 아니라 `0x70001000` 또는
`0x70001800`의 8 KB scratchpad 큐를 사용한다. 또한 같은 SIGNAL 바이트열이
메인 체인에도 존재한다는 사실만으로 `0x00145848`이 이벤트에서 실행됐다고
판정할 수 없다. 따라서 이 호출부 전용 시험은 기각한다.

반면 이벤트 중 디버거 화면에서 PC `0x00163258`, RA `0x00163550`이 직접
관찰되어 공용 VIF1 플러시 `0x00163520` 자체가 실행된 것은 확인됐다. 이에
새 시험본은 이 함수 입구를 훅하고 다음 조건으로 게임의 2D 스프라이트 빌더
`0x0013A6C0`을 호출한다.

- 논리 화면 폭/높이(`0x70000018`, `0x7000001A`)가 0이 아닐 때만 실행
- 게임의 페이드 사각형과 같은 상태 설정 함수들을 사용
- 텍스처를 끄고 전체 화면 scissor를 설정
- `(32, 360)`, `448 x 56`, 불투명 자홍색 사각형을 큐에 추가
- 원래 `0x00163520`의 두 prologue 명령을 재현한 뒤 정상 복귀

산출물은
`build/event-global-vif-engine-rect-probe-v19/Grandia3_v19_event_global_vif_engine_rect_probe.iso`이며,
SHA-256은 `cd72bdca9d27585ad0435c38a90859442d513033c1082276a873ddcdc5cad00b`다.
ISO 역추출 검증에서 교체된 `SLPM_659.76`은 빌드 입력과 byte-identical이다.

## 공용 플러시 시험의 실제 결과

초기의 code cave `0x001E7A10`은 ELF에서는 0으로 보이지만 실행 중 첫 워드가
`0x00000002`로 덮인다. 이 위치에 둔 trampoline은 첫 스택 명령을 잃어
타이틀 전 검은 화면을 만들므로 기각했다. 슬롯 4/5/6에서 실행 중에도 0으로
유지되는 `0x001E9DF0`으로 cave를 옮기자 정상 부팅했다.

현재 리소스 경로 `DATA/00030100.MDZ`를 `0x0020DC00`에서 확인하는 조건을
붙이고 공용 VIF 플러시 `0x00163520`에 사각형을 추가한 시험에서는 다음 현상이
관찰됐다.

- 알피나 방 진입 전 미란다와의 렌더링 대화에서는 사각형이 표시됨
- 알피나 방 진입 전환에서 사각형이 잠깐 표시됨
- 실제 알피나 방 렌더링 이벤트에서는 유지되지 않음

따라서 리소스 식별은 맞지만 공용 scratchpad 플러시 뒤에 패킷을 추가하는
순서가 틀렸다. 특히 그 시점에는 게임의 프레임 완료 `SIGNAL`이 이미 큐에
들어가 있어, 자막 패킷이 현재 프레젠테이션에 안정적으로 포함되지 않는다.

## pre-SIGNAL 삽입 성공

슬롯 8의 저장 CPU 문맥에서 RA `0x001ACDA0`을 추적하고 실행 카운터를 둔
시험으로 `0x00145800`이 컷신 중 매 프레임 실행되는 것을 확인했다. 이 함수는
GS `SIGNAL` 패킷을 만든 뒤 공용 플러시를 호출하고 완료를 기다리는 프레임
펜스다.

최종 훅은 `0x00145800`의 두 prologue 명령을 `0x001E9DF0` cave로 우회시킨다.
현재 리소스가 `DATA/00030100.MDZ`일 때만, 게임의 `SIGNAL`보다 먼저 16 QW
DMA/VIF/GIF 패킷을 제출한다. 패킷은 컷신의 기존 3D 상태에 의존하지 않도록
두 GS context 모두에 대해 `TEST`, `SCISSOR`, `XYOFFSET`, `PRIM`, `RGBAQ`,
두 `XYZ2` 꼭짓점을 직접 설정한다. 그 뒤 원래 prologue와 SIGNAL/flush/wait
경로를 그대로 수행한다.

별도 PCSX2에서 사용자 슬롯 8의 복사본을 패치해 재생한 결과, 실제 알피나
방 렌더링 이벤트 하단에 자홍색 사각형이 프레임 동안 지속 표시됐다. 최종
ISO는 새로 부팅해 언어 선택 화면까지 정상 진입하는 것도 확인했다.

- 빌더: `tools/build_event_frame_tick_sprite_probe.py`
- 최종 ISO: `build/event-frame-tick-sprite-probe-v19/Grandia3_v19_alfina_event_pre_signal_self_contained_gs_probe.iso`
- SHA-256: `b5f2345b4ecf6b261180f51f99da00ba2ba93054fd54a0a6e947a9f2b8118094`
- 사각형: 논리 좌표 `(32, 350)`, 크기 `448 x 60`

이 결과로 렌더링 이벤트 위에 내부 자막 레이어를 합성할 수 있다는 것은
입증됐다. 다음 구현 단계는 사각형 A+D 패킷을 글리프 텍스처 업로드와
문자별 스프라이트 패킷으로 확장하고, 보이스/이벤트 진행 상태에 자막 문장과
표시 시간을 연결하는 것이다.

## 고정 문자 형태 출력 성공

같은 pre-SIGNAL 훅에서 텍스처에 의존하지 않는 흰색 벡터 획을 GS SPRITE로
조합해 `HI`를 만들었다. 알피나 방 컷신 하단에서 두 글자가 매 프레임 유지되는
것을 별도 PCSX2와 슬롯 8 복사본으로 확인했다. 이로써 단색 면뿐 아니라 여러
획으로 구성된 문자 형태도 컷신 위에 합성할 수 있음이 입증됐다.

슬롯 8은 이전 공용 플러시 시험 ISO에서 저장됐으므로, 저장상태 시험본을 만들
때는 원본 SLPM이 아니라 해당 ISO의
`build/event-resource-gated-sprite-probe-v19/SLPM_659.76`을 기준으로 실행
파일 차이를 적용해야 한다. 원본 SLPM을 기준으로 패치하면 예전 `0x00163520`
훅이 메모리에 남아 새 cave와 충돌해 검은 화면 또는 GS 크래시가 발생한다.

- 문자 시험 ISO: `build/event-frame-tick-text-test-v19/Grandia3_v19_alfina_event_static_HI_text_probe.iso`
- SHA-256: `068c6ba25f39ed1731d55a113e5cc98976d5608f8e77764257b55a82b3160cb2`
- 별도 새 부팅 시험: 언어 선택 화면까지 정상
- 현재 범위: `DATA/00030100.MDZ` 장소 리소스 + pre-SIGNAL 프레임 경로

다음 단계는 벡터 획 시험을 실제 한글 폰트 텍스처/글리프 스프라이트로 바꾸는
것이다. 이벤트 ID와 보이스 타이밍 연동은 실제 한글 한 문장이 표시된 뒤에
추가한다.

## 고정 한글 문장 출력 성공

나눔고딕 Bold 24px로 `자막 테스트`를 래스터한 뒤, 연속된 가로 픽셀과 같은
구간의 세로 행을 병합해 62개의 GS SPRITE 사각형으로 변환했다. 한 번에 131
QW를 할당하면 화면이 멈추므로, 각 패킷이 16 QW를 넘지 않도록 획 4개씩
15 QW 패킷 15개와 마지막 11 QW 패킷 하나로 나눴다.

코드는 기존 안전 cave `0x001E9DF0`에 336바이트로 두고, 패킷 데이터는 슬롯
4/5/6/8과 pre-SIGNAL 캡처에서 모두 0으로 유지되는 `0x001E7B00..0x001E8AFF`
4KB 영역에 3,776바이트로 저장했다. 실제 알피나 방 컷신 하단에 흰색
`자막 테스트`가 지속 표시됐으며 새 ISO 부팅도 언어 선택 화면까지 통과했다.

- 한글 시험 ISO: `build/event-frame-tick-korean-test-v19/Grandia3_v19_alfina_event_korean_subtitle_test.iso`
- SHA-256: `27389d3c6a6787a00e13a44c2cda0feff602dc18db41b438ed8fe9d15244a37c`
- 표시 위치: 논리 좌표 `(196, 364)`, 래스터 크기 `120 x 22`
- 현재 제한: 고정 문구이며 `DATA/00030100.MDZ` 장소 전체의 해당 프레임 경로에서 표시

따라서 실제 한글 자막 문장을 컷신에 합성하는 렌더링 가능성은 확정됐다.
다음 과제는 고정 패킷을 문장 테이블/이벤트 또는 보이스 상태에 따라 선택하고
표시·교체·해제하는 런타임 상태기로 바꾸는 것이다.
